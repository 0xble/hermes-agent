# Quiet continuation notices across waits

## Independent hypothesis (frozen 2026-10-12T02:30:40Z)

Base: `b2b00470079b08b2e4ee3b3f1c2e46e1ab6610b8` (maintained fork origin/main). Installed release: `881af4c2805230cad2dc10e539393f798114edc4`. `git diff` shows no differences between these commits in `hermes_cli/goals.py` or `gateway/run_goals.py`.

The native goal continuation notice is not a model reply: `GoalManager.evaluate_after_turn` commits a decision and `GatewayGoalsMixin` defers its `message` to the adapter's post-delivery callback. Instructions and reply filtering cannot prevent this separate notice.

Two defects explain the reproduction. `GoalState.clear_wait(preserve_notice_key=True)` preserves only the parked key and unconditionally clears the continuation key, including when parking, lifting timed/session/PID waits, and committing an idle CAS clear. A fresh manager therefore sees no prior continuation notice and republishes an unchanged reason. Separately, an intentional automatic silence marker skips the judge but synthesizes CONTINUE with `last_reason` (or a default); the ordinary notice creation branch can advertise that stale reason as fresh progress.

Smallest complete correction: preserve the existing continuation identity alongside the parked identity when callers request preservation, and make synthetic silent CONTINUE ineligible to create or consume a continuation notice identity. Keep age-notice reset independent. Keep judging, scheduling, budget/backoff, important completion/blocker notices, and explicit command receipts unchanged. No new knob, state schema, plugin, dependency, migration or platform-specific code is required. Explicit pause/resume/unwait still resets notice identity through the existing nonpreserving path.

The existing `goals.auto_notices` setting is consumed by `agent.inline_tool_executors._goal_receipt_text` for committed `goal_set` tool receipts, not by goal evaluation or gateway continuation notices. Disabling receipts neither repairs durable dedupe nor protects model-selected silence. Broadening it to suppress all lifecycle notices would change a separate policy and hide useful outcomes.

Before-fix boundary: real `GatewayRunner._run_post_turn_hooks` -> provenance -> `GoalManager` snapshot evaluation -> SQLite commit -> adapter post-delivery callback/send, plus durable reload after closing DB handles. Only auxiliary verdict and external liveness are controlled. `HERMES_TEST_FILE_RETRIES=0 scripts/run_tests.sh tests/gateway/test_goal_continuation_notice_dedupe.py -q` returned **8 failed, 4 passed** on the unchanged production base (3.07s pytest; 4.0s runner). Failures cover new silent continuation notices, timer/session/PID/idle-CAS lifts replaying an unchanged reason, and the extra silent notice preceding completion/blocker delivery. Red log: `/Users/brianle/.hermes/cache/scratch/goal-quiet-before.log` (local evidence, not a portable dependency).

Every wait lift is silent: the gateway idle path and the TUI poller no longer send a `▶ Goal wait ended — resuming.` notice (PR [#432](https://github.com/0xble/hermes-agent/pull/432)). Production Telegram delivery and active runtime acceptance remain parent-owned, not inferred from the captured adapter.
