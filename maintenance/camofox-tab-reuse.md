# Camofox tab reuse

Load this unit when changing Camofox task bindings, end-of-turn browser cleanup, tab adoption, or `browser_handoff` continuity.

## Required behavior

- **Automatic owned-tab cleanup.** End-of-turn `camofox_soft_cleanup` closes every disposable tab the task created through `POST /tabs`, including tabs whose bindings were replaced, while retaining the account, adopted/user tabs, explicit keeps and vault protection. Cookies and managed profiles persist. Named-account bindings remain managed even with `browser.camofox.managed_persistence: false`; that setting controls unnamed sessions, not explicit handoffs. Visibility (`browser.headed`) is not a keep: native Camofox cleanup runs in headed and headless modes. A carried binding may switch account next turn; within a turn the account stays fixed. Ephemeral identities also close only exact owned tabs. Managed identities are never reaped. For ephemeral identities, the reap is skipped if a handoff is in flight, any session or owned record remains for the userId, the tab listing is unreadable, or the listing is non-empty.
- **Explicit single-tab close.** `browser_close` is Camofox-only and defaults to the caller's current tab, or accepts an exact caller-owned `tab_id`. It requires the existing creator-ownership record keyed by profile, task, server and tab. Merely adopted/shared pages and popup reservations do not grant destruction ownership. Protected data, sibling bindings, handoffs and cross-process leases remain fences. DELETE is pinned to the captured server and identity without redirects, runs outside the binding lock, and succeeds only after a valid `GET /tabs` proves the exact tab absent. A failed or ambiguous readback restores retry ownership without replacing a concurrently selected tab. It never deletes a session or account.
- **Release at agent close.** `AIAgent.close()` releases the bindings of every task id the agent ran (`release_task_bindings`), closing disposable owned tabs a cut turn left open. It never uses the close-time `session_id`, because temporary hygiene and compression agents share the live session's id but own none of its tabs.
- **All agents close their own disposable tabs.** `release_task_bindings(..., close_created_tabs=True)` retries exact owned-tab cleanup when any agent closes, including a top-level interactive session whose turn was interrupted. Ownership is keyed by profile, task lineage, server and tab ID; changed server configuration cannot direct an old tab deletion at a new server. Failed turn-cleanup deletes retain retry state and log a warning. After agent close, surviving or failed-delete ownership and leases are abandoned; protected-data quarantine remains until destruction is confirmed. A stale-tab response clears obsolete ownership but retains durable quarantine until the server listing confirms absence or an exact DELETE succeeds. Bindings and ownership transfer together across compression; unused continuations close with their originating agent, while used continuations belong to their live owner. Adopted, shared-identity and explicitly kept tabs are never cleanup targets; unreadable quarantine fails closed. Protected owned tabs survive only while a live owner holds their protection, then exact cleanup destroys them immediately and clears quarantine, ownership and leases. Protected tabs without this task's create-ownership are never destroyed.
- **Cross-process leases.** Native bindings hold exclusive OS locks keyed by Camofox server, identity and tab. The single coordinator at `~/.local/state/hermes/camofox-tab-leases` is host-wide and independent of process `HERMES_HOME` and profile overrides, so an external identity shared across gateways, CLIs and profiles cannot lose a live tab to another Hermes process. Once per process at first claim, best-effort pruning skips files modified within ten minutes to avoid briefly blocking fresh claims. Older crash-residue files are removed only after taking an exclusive lock and checking that the pathname still addresses the locked inode; age alone never authorizes removal. Adoption and deletion refuse a live holder's lock; unavailable state directories or lock providers degrade to process-local ownership with one warning instead of stranding newly created tabs. POSIX uses `fcntl`; Windows declares `portalocker` directly. Release unlinks the lock pathname while still holding the lease, and claim validates the locked inode against that pathname so pre-opened orphan handles cannot become authoritative. Process death releases the lock. Within a process, cleanup fences a tab and removes its ownership under the sessions lock, performs HTTP DELETE outside that lock, then restores retry ownership on failure. A separate closing fence survives transient server-listing omissions and excludes adoption/handoff binding until DELETE completes. Tests isolate the lease root and release all handles after each case.
- **Explicit keeps.** A successful `browser_handoff` atomically keeps any owned tab it exposes and preserves the shared visible page; in-flight handoffs block deletion. Confirmed `release=true` relinquishes this task's keeps without claiming user-created tabs. Internal `keep_task_tabs` changes only exact owned resources, never unknown tabs. Agent close drops kept/handoff ownership without deleting the tab and releases its OS lease unless a live sibling still binds it; that sibling releases the lease when its own binding ends.
- **Task-id-less turns.** Callers that omit `task_id` (CLI one-shot, direct `AIAgent`) get a new id each turn; `_bind_turn_identity` moves the managed binding to the next turn's id.
- **Compression carries the binding.** Gateway and CLI turns use the session id as browser task id, and compression rotates it. `_carry_session_state_to_child` copies the managed binding to the continuation id. The old id serves the rest of the turn, then its soft cleanup drops it, quarantining a protected tab.
- **Adopt before creating.** With no binding, `_ensure_tab` lists `GET /tabs` for the session's own userId only. It refuses tabs bound to another task in this process, protected or quarantined tabs (memory and disk; unreadable quarantine fails closed), and tabs this process saw reported stale. It prefers the target URL's origin, then the newest `__shared_identity__` tab, then the newest tab of the task's own group. Other tasks' tabs are left alone, except that an external `user_id` with `adopt_existing_tab` may take any eligible tab. Selection and binding happen under the sessions lock.
- **Popup selection.** `browser_tabs()` lists only the current task's reserved tabs and opener-affine popups from `GET /tabs`. `browser_tabs(tab_id=...)` changes subsequent browser actions and requires a fresh snapshot for refs. Task-group inheritance proves affinity only with positive `hermes_identity` provenance from the named-account, managed-persistence, or ephemeral resolver. External `user_id` identities can deliberately share both configured and truncated fallback task groups with other applications, even when broad adoption is disabled. External identities, broad-adoption sessions, shared/human groups, and sessions missing provenance require explicit `openerTabId` descent from an owned root for unknown popups. Task carry preserves provenance rather than deriving trust from the `managed` or adoption flags. Other live tasks, cross-process leases, closing fences, stale IDs, and protected/quarantined tabs remain excluded. Enumeration reserves the opener and popups together so switching cannot make the opener adoptable by another task. Reservations transfer across compression and release at task close. Discovery does not make adopted tabs cleanup-owned.
- **Capability reporting.** Camofox console capture returns `success=false`, `supported=false`, and `error_type=unsupported_capability`, not an empty successful capture. Console expressions still use evaluation. Annotated vision retains the screenshot, reports unsupported numbered overlays, and surfaces snapshot/stale-tab warnings without presenting the screenshot as a fresh interactive page.
- **Handoff is atomic.** While a handoff's `/open` is in flight, adoption skips the shared identity group. The handoff sends the task's existing `tabId` when it has one, binds only an unclaimed returned tab (or its own returned tab), and never steals or clears another live task's binding. If the visible window shows another task's tab, the caller remains model-detached and keeps working in its own tab. Release sends the caller's current `tabId`, refuses an unbound caller rather than issuing an account-wide release, and keeps the task binding on the parked path because the paired server preserves the tab. On hosts without a parking display, retry only a typed HTTP 409 `context_restart_required` (`open`) or `context_close_required` (`release`) once with the corresponding `allowRestart: true` or `all: true`. This explicitly preserves pre-parking whole-context relaunch/close behavior, including loss of all live page state in that identity. Report that loss in the tool result. Never widen successful parked release to `all: true`, and never reinterpret busy, authentication, malformed or unrelated errors as consent. After legacy release, an action on the stale binding fails closed until explicit navigation.
- **Page actions after loss.** A page action adopts only for a session never bound in this process (new task, gateway restart). A binding cleared later (stale tab or another task's protected handoff) is rebound only by `browser_navigate`, so a page action never continues on a replacement tab. Stale-tab records are pruned to the server's listing on each adoption.
- `adopt_existing_tab` now governs only external `user_id` identities. Hermes-managed identities always adopt their own tabs.

## Provenance and patches

- Fork patch identity: `camofox-tab-reuse`.
- Explicit-close design check (upstream main `088f657ecf77674c7b8e2ededf4e3576d82e042c`): merged [#5792](https://github.com/NousResearch/hermes-agent/pull/5792) intentionally removed the former whole-session `browser_close` as redundant with automatic cleanup. This user-requested fork divergence exposes only immediate, creator-owned single-tab closure with readback, not the retired whole-session action. Automatic cleanup remains unchanged. Closed [#71375](https://github.com/NousResearch/hermes-agent/issues/71375) requests tab list/switch/close capabilities but does not establish an upstream equivalent to this ownership contract. Retirement: adopt an upstream implementation only if it preserves exact creator ownership, profile/server isolation and truthful absence readback.
- Follow-up fork patch identity: `camofox-task-tabs-capabilities`. Implements the public dispatch for the existing popup-tools task `db79dcc6-78a8-438d-b7cd-58d6673a6284` at the public dispatch boundary. Repository branch/history and fork issue/PR searches found no unfinished implementation to resume. Named handoff scoping and popup affinity remain fork-only. No upstream publication is authorized.
- Defect: `cleanup_task_resources` → `cleanup_browser` → `camofox_soft_cleanup` dropped the task's binding every turn except in global headed mode, so each turn's `_ensure_tab` posted `/tabs`. Adoption was off by default and picked the newest tab of any group. After `browser_handoff` the next turn opened a different tab from the one the user had logged into (37 of 149 handoffs since 2026-09-09).
- Upstream search (2026-10-10): open [#20511](https://github.com/NousResearch/hermes-agent/pull/20511) preserves per-turn Camofox sessions (opposite of disposable owned-tab cleanup), and [#103591](https://github.com/NousResearch/hermes-agent/issues/103591) covers real-profile Chrome processes rather than Camofox ownership. Neither supplies safe task-owned tab cleanup. Earlier search (2026-10-06): no issue or PR covers per-turn Camofox tab loss. Related open issues [#80276](https://github.com/NousResearch/hermes-agent/issues/80276) (stale 410) and [#92361](https://github.com/NousResearch/hermes-agent/issues/92361) (navigate hardening) do not. Named accounts and handoff are fork-only, so this patch stays fork-only.
- Upstream design check (2026-10-12, main `835c3dd038d903182a66ecc45e34bf5e0de65f00`): merged [#24499](https://github.com/NousResearch/hermes-agent/pull/24499) preserves externally managed identities; related open [#20511](https://github.com/NousResearch/hermes-agent/pull/20511) retains all per-turn sessions. Neither implements fork-only named handoff with persistence disabled. Soft cleanup must consult the actual session's `managed` flag while still deleting disposable owned tabs; the existing config and external-identity paths remain supported.
- Follow-up fork patch identity: `camofox-handoff-own-tab` (`Fork-Patch:` trailer). The paired Camofox server now honors `/open` `tabId` and preserves the browser during visibility changes; Hermes must preserve the task binding and refuse cross-task rebinding. Upstream search (2026-10-09): no related upstream issue or PR found beyond the existing Camofox tab-management work; this remains fork-only.
- No-park compatibility design check (2026-10-24, upstream main `1c0cd667746d3395fe9e1b6c74f8f85952486f18`): upstream search for Camofox handoff returned no matching issue or PR. Named identity lifecycle remains fork-only. Camofox [#35](https://github.com/0xble/camofox-browser/pull/35) introduces typed consent errors and [#41](https://github.com/0xble/camofox-browser/pull/41) supplies inline uploads. Client negotiation restores the former legacy transition only after an explicit no-park conflict, so no server policy change is needed. Retirement: remove the negotiation when all supported servers preserve tabs without a display, or upstream supplies this lifecycle.
- Surfaces: `tools/browser_camofox.py`, `tools/browser_camofox_handoff.py`, `tools/browser_camofox_leases.py`, `agent/client_lifecycle.py`, `agent/chat_completion_helpers.py`, `agent/conversation_compression.py`, `agent/turn_context.py`, `hermes_cli/config_defaults.py`, browser docs. Native lifecycle ownership extends these existing core owners; Safari/Chrome automation is a separate capability-edge plugin in the agents repository, not a new browser tool or core desktop adapter.

## Verification

`scripts/run_tests.sh tests/tools/test_browser_close.py` covers public close dispatch, exact-tab HTTP readback, ownership refusals, malformed/unavailable readback, ambiguous DELETE reconciliation, retry state, and in-flight sibling isolation. Its 2 default/explicit closure cases fail on the base with `Unknown tool: browser_close`.

`scripts/run_tests.sh tests/tools/test_browser_camofox_tab_reuse.py` drives the real tool dispatch, real end-of-turn cleanup and compression handoff against a stub Camofox server with a temporary `HERMES_HOME`. Its core tests fail on the pre-patch source. `tests/tools/test_browser_camofox_capabilities.py` covers release scoping, truthful diagnostics, popup discovery/selection, sibling isolation, lease/quarantine fences and continuation cleanup through real registry dispatch and a stub HTTP server. Also run the other `tests/tools/test_browser_camofox*.py` files, `tests/agent/test_browser_output_egress.py`, and `tests/tools/test_browser_vault.py`. A live check may use the local Camofox only with a throwaway identity from a temporary `HERMES_HOME`, deleting its session afterwards.

## Retirement and rollback

Retire when upstream ships per-turn binding retention and safe adoption for managed Camofox identities with handoff continuity. Roll back by reverting this patch's commit. No server, profile, credential or state migration occurs. Quarantine is removed only when tab destruction is confirmed.
