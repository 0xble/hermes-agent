# Managed browser identity and authentication

This responsibility covers both browser backends, identity claims, snapshot authentication and process/CDP ownership. The [root contract](../MAINTENANCE.md)
requires it on every run and owns shared adoption/publication policy.

HERMES-133 retires the unsafe immutable snapshot path: earlier HERMES-077 descriptions of that historical path do not authorize its resurrection. HERMES-077's remaining bounded-backup contract still applies.

## Coupled current adaptations

- Browser identity recovery reuses verified endpoints before invalidating Browser Use attachments. Non-sidecar session entry enforces persisted Camofox ownership before cache access or creation. Regressions: `tests/tools/test_browser_real_profile.py` and `test_browser_camofox_named_identities.py`. Source rollback must preserve durable backend claims.

- Snapshot browser cleanup reuses the existing ambiguity-rejecting profile-argument parser and current browser inventory. Repeated switches, arguments after a terminator, malformed argv and escaped snapshot paths cannot authorize termination. `tests/hermes_cli/test_browser_snapshot_process_ownership.py` retains positive owned-tree cleanup coverage. Rollback of the inventory repair alone restores a runtime NameError; do not reintroduce first-argument ownership selection when adopting upstream cleanup.

- HERMES-080 again declares `browser.real_profile_refresh: launch` in config defaults. The existing `initial` mode roundtrips through the config CLI without an unknown-key notice; live profile state and refresh policy remain unchanged. Regression: `tests/hermes_cli/test_browser_policy_config_failures.py` and existing real-profile lifecycle tests.

- A real-profile browser cache hit refreshes the identity-scoped attachment session in both the legacy and named lanes, so the orphan reaper cannot reap a socket still in use.

- The browser immutable-SQLite fallback is retired: an immutable reader can expose uncommitted pages in a hot-journal database. An inability to obtain a trustworthy snapshot must not be reported as a safe read. Browser lifecycle recovery still requires exact daemon/process ownership.

- A named browser identity is checked against the backend before the durable claim.

- Snapshot reuse and the launch overlay refuse a profile whose `SingletonLock` names a live or unverifiable owner.

- Browser Use reload retires a pending marker whose recorded daemon is verifiably gone, generation-scoped.

### HERMES-077 — Bound locked real-profile authentication refreshes

- **Independent hypothesis (2026-08-29):** `_copy_auth_file()` opens Chromium authentication databases with `timeout=5` and then calls `sqlite3.Connection.backup()` without a progress deadline. Python's connection timeout does not bound the online-backup loop: when a live Chrome process holds `Login Data` or `Web Data` under an exclusive lock, `backup()` reports `SQLITE_BUSY`, sleeps, and retries indefinitely inside the gateway worker. The outer tool deadline abandons that non-cooperative worker without releasing the per-identity runtime lock, so every later `browser_exec` call for that identity blocks before Browser Use starts. Live macOS evidence found all three configured profiles stuck in `pysqlite_connection_backup` while their cookie databases remained readable; a synthetic `BEGIN EXCLUSIVE` database reproduced the unbounded call.
- **Summary:** Temporarily backports upstream PR #96659 exactly, then bounds the remaining immutable-first SQLite backup: `_copy_auth_file()` reuses the deadline-bounded `_safe_copy_db()` helper with a ten-second budget before falling through to the existing raw-copy path, and the immutable snapshot backup uses the same busy/locked deadline instead of an unbounded `backup()` call. A live Chrome process can no longer strand a gateway worker and its named-identity lock inside CPython's unbounded `sqlite3.Connection.backup()` retry loop.
- **Surfaces:** `hermes_cli/browser_connect.py`; `tests/tools/test_browser_real_profile.py`; this record.
- **Upstream tracking:** Open issues #96646 and #96661 report the same macOS/POSIX real-profile hang. Current upstream `main` contains an alternate immutable-first SQLite path from `fix(browser): real-profile browsing on macOS - launch real binary, kill sqlite hang, normalize profile copy`, but the maintained fork's named-identity implementation still contains the unbounded call and cannot adopt that broader conflicting change wholesale. Checked 2026-08-29.
- **Upstream PR:** Direct and CI-green: open PR #96659, `fix(browser): bound the real-profile auth backup so a locked source falls through to raw copy`, head `14657740ab14502051baa1bae2f367856d7aad96`. Its complete two-file patch applies cleanly to fork `main`; the archived `0600` patch is `/private/tmp/hermes-pr-96659.patch` with SHA-256 `0e21f854016aedccfec5d3c66cc25fcdbb90b9567a603ecf104f1118450dedf0`.

GREEN uses a real `BEGIN EXCLUSIVE` SQLite source and proves `_copy_auth_file()` returns within five seconds, falls through to a readable raw copy on POSIX, and cannot livelock. The complete real-profile, backup-helper, identity, Browser Use, lint, manifest, maintained-fork, and live three-identity canaries are required before promotion.

### HERMES-133 — Unsafe immutable auth snapshot retired

- **Historical intent:** The September 8 workaround used `immutable=1` to avoid exclusive locks held by live Chrome. Its assumption that rollback-journal main files contain only committed data was incorrect.
- **Retirement evidence (September 11):** A real SQLite database with 500 rows, a ten-page cache and an uncommitted exclusive UPDATE spilled dirty pages. An immutable reader observed 494 uncommitted rows. WAL absence cannot establish a safe snapshot.
- **Current behavior:** Use upstream's bounded coordinated `mode=ro` online backup. Exclusive source or destination locks fail safely. Retry after the owning browser releases its lock. No raw-copy or immutable fallback.
- **Regression:** `scripts/run_tests.sh tests/tools/test_browser_real_profile.py` covers dirty-page spill, bounded lock failure, destination preservation, and committed WAL copying.
- **Rollback:** Do not restore the disproved committed-image assumption. Any future lock-avoiding implementation needs a proven consistent snapshot mechanism.
- **Additional historical subjects (optional provenance):** `fix(browser): snapshot auth DBs from the committed image`.
