# Repository CI contract

`./bin/ci preflight` is fast, credentialless local feedback, including the Fork-Patch ownership check the gate's static lane enforces, so an unowned identity fails before the push rather than in a hosted gate; the optional `.githooks/pre-push` hook invokes it (set `HERMES_SKIP_PREFLIGHT=1` to bypass). Existing global `core.hooksPath` takes precedence: this repository does not install or override hooks. `./bin/ci gate <40-character-head-sha>` is the blocking Linux PR profile: static policies, four focused agent/gateway/CLI Python files, and six bounded Node workspace checks (the complete nine nonrelease workspace checks run nightly). The complete non-integration Python suite runs nightly, not per PR. `./bin/ci nightly <sha>` runs all seven source lanes on Linux, including full Python, E2E, docs, Rust, and container lint. `./bin/ci nightly-native <sha>` selects the pre-existing actual-host marked native suite on hosted macOS and Windows as a blocking nightly qualification, not a PR gate. All three exact-SHA profiles reject a wrong SHA or dirty tracked tree before setup, immediately before checks, and after checks (including failed checks). The existing `setup`, `check`, `full`, `list` and partial `check --lane` interfaces remain available.

The fork's `main` had **no workflow files** at the original CI migration base (`9abae85c03`); its inherited CI workflows were retired earlier. [portable-ci.md](portable-ci.md#coverage-allocation-before-workflow-removal) maps all 36 original files and checks. The migration added `gate.yml` and `nightly.yml`; this change adds native macOS and Windows jobs **only to nightly**, following Brian's approval for the public fork. The PR gate remains Linux-only. The workflows use a pinned Node Linux image, SHA-pinned checkout, exact ref assertion and read-only token permissions. The PR's `qualification` job is the sole aggregation status; do not require a cancelled/skipped lane as success. Nightly's concurrency never cancels an earlier night. Existing upstream-sync automation is external to this repo's current workflows and is not modified.

Cost estimate (billed Linux runner minutes; workload dependent): before retirement the last 30 job-bearing CI runs averaged ~60 min, Nix ~5.6/run, Docker ~1/run, plus review-comment ~4/run across 100 triggers; roughly **70 min/PR**, excluding duplicate push runs and Windows/macOS matrices. The replacement is one Linux focused source gate estimated **8–18 min/PR plus ~1 min qualification**; nightly broad Linux profile roughly **55–70 min/night plus ~1 min qualification**, with additional hosted macOS/Windows native jobs. The public repository incurs no hosted native platform minute charges. The former `CI review comment` workflow started on every `CI` **in_progress** and polled up to 50 minutes; among the last 100 runs its 60 active jobs billed roughly 401 Linux minutes, 61 of them cancelled. Do not revive it. If comments become a requirement, use a completed-event single commenter with no polling and restrict its write privilege to a trusted workflow, not PR-controlled gate code.

A passing source gate does not certify external integrations, Nix, native installers, image publication, or signed desktop releases. GitHub Actions billing limits may prevent all jobs from starting; until an actual hosted run executes, local verification is evidence only and `qualification` cannot be claimed green.
