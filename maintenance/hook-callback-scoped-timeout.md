# Call-scoped plugin-hook timeout refusal

- Fork patch identity: `hook-callback-scoped-timeout`.
- Required behavior: a synchronous bounded callback timeout vetoes only that invocation. A fresh call evaluates its own arguments without a callback-wide wall-clock cooldown. Two abandoned invocations still running (`K_ABANDONED=2`) refuse admission with `callback_hung`; completion below that threshold permits the next call immediately. A separate `LIVE_BUDGET=32` counts all live and reserved invocations per hook/callback, atomically before worker creation; exhausted healthy capacity refuses with `callback_busy`. The hung threshold must not throttle healthy parallel tools.
- Protection: policy-hook timeout, duplicate-running, hung, busy and worker-start failure outcomes always become `action: block` with a nonempty message. Other plugins' approve/modify results cannot override that veto, and a late approval cannot resurrect a timed-out tool. Observer skips remain fail-open, preserving later observers and the original result. Existing shell applicability, shell timeout margin and `fail_closed` exceptions, privacy checks and safe-worker exclusions remain intact.
- Implementation surfaces: `hermes_cli/plugins_dispatch.py`, manager bookkeeping in `hermes_cli/plugins.py`, and unload-all cleanup in `hermes_cli/plugins_ledger.py`. No change to `ainvoke_hook`, the global callback timeout default, or source-guard.
- Limits: Python daemon workers are abandoned, not killed. The bound applies to one manager/registration generation: unload-all clears its accounting even if old workers remain alive. Repeated reloads are not a process-lifetime thread bound and must not be used to escape hung refusal. Identity-conditional worker cleanup prevents old completions from deleting newer tokens. Repeated just-over-deadline callbacks can each consume a full timeout when they finish between calls; this contains resource growth, not source-guard latency.
- Upstream overlap: [#140078](https://github.com/NousResearch/hermes-agent/pull/140078) scopes suppression to sessions but retains the timer; [#141239](https://github.com/NousResearch/hermes-agent/pull/141239) adds registration tokens; [#129378](https://github.com/NousResearch/hermes-agent/pull/129378) adds session-aware gates and named timeout messages; [#132111](https://github.com/NousResearch/hermes-agent/pull/132111) addresses shell matching, wrapper margins and shell fail-closed policy. Preserve those distinct contracts during reconciliation.
- Retirement: remove only after released upstream passes the full completion-driven refusal, atomic live/reserved-budget and fail-closed contracts without this patch. A per-session timer alone is not equivalent.
