# Gateway launchd QoS

## Contract and placement

The macOS gateway LaunchAgent sets `ProcessType` to `Interactive`. With no
`ProcessType`, launchd starts the agent's threads at UTILITY QoS (0x11), and
every child inherits it, including the stderr wrapper (`ps` PRI 20) and the
gateway's own tool and test subprocesses. Utility QoS ranks the gateway's CPU
and disk I/O below any terminal-launched workload, which runs at
USER_INTERACTIVE. `Interactive` starts the agent at DEFAULT QoS (0x15), the
level apps get. `Background` is known to starve services on this host. It made
Camofox about 17x slower at load 65 on 2026-10-04.

The plist is generated by `generate_launchd_plist` and rewritten by every
install and release promotion, so a hand edit or a config overlay would not
survive. No config surface exists, which makes the one-key template change in
`hermes_cli/gateway_launchd.py` the smallest adequate patch.

Fork patch identity: `gateway-launchd-qos`.

## Evidence

On 2026-10-11, throwaway LaunchAgents ran a probe through the gateway's
osascript, sh and python chain. The probe read `qos_class_self()` in itself and
in a child, then timed a fixed CPU loop while 56 default-QoS spinners
oversubscribed the 28 CPUs two to one. The Standard runs (no ProcessType)
reported QoS 0x11 and took 1.38s and 1.73s. The Interactive run reported 0x15
and took 0.187s. Children inherited the parent's QoS in both cases.

The same harness found no measurable change to F_FULLFSYNC or plain fsync
latency from the gateway QoS or from lowering a synthetic CI load's I/O tier.
Device-flush stalls are addressed separately by moving the WAL checkpoint off
the writer lock.

## Verification and retirement

Regression: `tests/hermes_cli/test_gateway_service.py::TestGeneratedSystemdUnits::test_launchd_plist_runs_gateway_as_interactive`.
After the next restart, a gateway thread should report DEFAULT QoS and the
stderr wrapper should no longer sit at `ps` PRI 20.

Retire this patch when upstream's generated plist sets an equal or higher
`ProcessType`. Roll back by reverting the commit that carries
`Fork-Patch: gateway-launchd-qos`. The next install or promotion then rewrites
the plist without the key.
