# Browser File Transfer

Load this unit when changing `browser_upload`, `browser_downloads`, Camofox tab actions, or the upload/download transport.

## Required Behavior

`browser_upload` attaches Python-host files through Camofox's `POST /tabs/{tabId}/upload`. `browser_downloads` lists captured downloads from the owned tab and imports a selected download onto the Python host. Both tools are registered only in Camofox mode and use the existing named-account, per-task tab binding and private-page guard.

- **Path Checks:** Check each raw upload path with `agent.file_safety.get_read_block_error` before resolving it, then check the resolved path again. Resolving an NT/device namespace path can itself trigger SMB authentication. Denied paths and missing files never reach the server.
- **Upload Transport:** Send `files: [{name, mimeType, dataBase64}]`, not a server-local `path`. Preserve the basename and exact bytes, including Unicode names and empty files. Use MIME inference with an `application/octet-stream` fallback. Bound aggregate decoded upload bytes at 20 MiB, including files that grow while being read. Do not stage files locally or require a shared filesystem. The legacy `CAMOFOX_UPLOADS_DIR` and `browser.camofox.uploads_dir` settings do not affect inline uploads.
- **Trigger Bypass:** When a trigger is named, count top-level file inputs through `/evaluate` before posting `/upload`. Walk open shadow roots as Playwright does. Proceed only with a verified integer zero. A positive count, unavailable evaluate route, or missing/invalid count refuses the upload. Omitting both trigger fields retains the server's first-input behavior without requiring `/evaluate`.
- **Chooser Wait:** Preserve Camofox's own 12-second chooser wait and the client's 45-second minimum HTTP timeout. Increasing the chooser wait can turn a successful attachment into a server timeout.
- **At-Most-Once Dispatch:** Never automatically replay an upload after dispatch, including through redirects or fallback to the legacy path contract. A failure or invalid confirmation can follow a successful browser attachment. Return guidance to inspect the page before retrying.
- **Download Transport:** With no `download_id`, request metadata only. With an ID from that listing, request `includeData=true&maxBytes=20971520`. The server returns the tab's download list, not one selected record, so stream and bound the entire decoded HTTP response at 28 MiB before parsing it. A large multi-file response can be refused even when the selected file alone fits. Do not widen the cap or silently return a Mac path.
- **Stale-Tab Errors:** Preserve a bounded HTTP error body for the existing stale-tab classifier before closing its response. Clear a confirmed stale binding without replaying the download. Reuse the same 28 MiB transport cap on successful and failed responses.
- **Download Validation:** Validate the response tab ID, record shape and unique IDs, safe basename, byte count, successful capture, available content, strict canonical base64 and exact decoded size. Refuse selected files over 20 MiB. Never use a remote filename or ID as a parent directory or trust a server-local path.
- **Artifacts:** Save a selected download into a newly allocated private directory under the active profile's `browser_downloads` directory. Use exclusive creation so repeat saves and duplicate filenames cannot overwrite an existing artifact. Preserve the filename and return `output_path`, MIME type and byte count. Do not return or log contents, base64, remote filesystem paths or arbitrary server error bodies.

## Provenance And Contribution Route

- Fork patch identity: `browser-upload`.
- This remains an intentional fork extension, not an upstream contribution. The existing Camofox-mode service-gated browser tool is the smallest supported surface for byte transport bound to the current browser identity and owned tab. No new service, dependency, configuration framework or capability abstraction is needed.
- Upstream rechecked on 2026-10-24 at `NousResearch/hermes-agent` main `99fcd6944360925943688d30c39ec9a490ccdeb1`. Root, contribution, tool and test guidance is unchanged from the original `bac34e9e9946c9c6a9ce7ce64efadd47f8fa375b` inspection. Preserve the fork's existing adapter rather than introduce a second browser owner.
- Related, not adopted: [captured-download issue #52939](https://github.com/NousResearch/hermes-agent/issues/52939) and [PR #52979](https://github.com/NousResearch/hermes-agent/pull/52979), open at `1e46b45f3f48ba0627e65e2190ec7de6be4addc0`. The PR proposes separate listing/saving tools, permissive base64 decoding and caller-selected output paths. Its automated review identifies missing static-toolset exposure, private-page checks and Camofox-only availability. This fork already routes through those existing guards and registrations, and additionally requires bounded responses, strict decoding, isolated artifacts and at-most-once uploads. Keep 1 explicit download tool without exposing base64 to the model.
- Upstream placement: [core extraction #143146](https://github.com/NousResearch/hermes-agent/pull/143146) merged as `e5710273103fbc4c749217977769f0c3e799be9c`, followed by [catalog #143484](https://github.com/NousResearch/hermes-agent/pull/143484). The catalog pins [official plugin #161](https://github.com/NousResearch/hermes-official-plugins/pull/161) at `190593f4ce4c481a80ed27448535c867c5c6e27f`. That plugin registers neither upload nor download tools and deliberately registers nothing on cores, including this fork, that still bundle Camofox. Latest stable `v0.22.5` at `bf0203a794a07aac3ff764972ab9087baa4e4f4e` predates the extraction. Extending this fork's current adapter is the smallest compatible change, not a reason to restore removed core tools upstream. Port the byte-transfer and named-identity behavior to the plugin owner when the maintained fork adopts the extraction.
- Inline server contract: [0xble/camofox-browser#41](https://github.com/0xble/camofox-browser/pull/41), merged as `fcb0612d4f73eac022201ffe727affbdaad30fed`. Preserve its additive legacy-path compatibility, canonical encoding, decoded-size limits and attachment-at-most-once behavior.

## Verification

Use the repository runner for `tests/tools/test_browser_file_transfer.py`, `tests/tools/test_browser_upload.py`, the directly relevant Camofox ownership/account/timeout suites and browser registry/toolset tests. The transfer fixture runs a real loopback HTTP peer on an ephemeral port with an isolated Hermes home and synthetic persistent identity. It verifies the actual registered tool path and wire payload without using an authenticated browser profile. The server's separately owned real-engine suite verifies browser attachment bytes and cross-origin chooser behavior.

When tool registrations change, also run `tests/ci/test_prompt_surface.py` and `tests/hermes_cli/test_shared_metrics_efficiency.py`. Regenerate the committed prompt-surface snapshot with `scripts/ci/prompt_surface.py render` and keep the current shared-metrics tool-name vocabularies aligned with the built-in registry. Preserve existing schema bounds and prompt text unrelated to the tool change.

## Rollout And Rollback

Install and activate the matching server first, then the Python client. Source publication does not authorize either installation or activation. A server lacking the inline contract must fail visibly, never trigger a legacy-path retry. Revert or deactivate the client before removing inline server support. Existing server-side path callers remain compatible. Captured local artifacts remain ordinary profile-local files.

Retire this divergence when released upstream supports equivalent Camofox byte transfer, ownership and artifact safety with the behavior tests passing.
