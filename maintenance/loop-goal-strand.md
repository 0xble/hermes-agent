# Loop–Goal Stranding Repair

Fork patch identity: `loop-goal-strand`.

A goal continuation judge runs in deferred post-delivery bookkeeping. The adapter joins that bookkeeping for only `POST_TURN_DELIVERY_WAIT_S` (60 seconds); if the auxiliary judge outlives the join, the adapter releases its session guard before the judge enqueues the continuation. `_enqueue_fifo` records the synthetic event but historically did not start a drain, so the event remained in the pending slot until unrelated ingress arrived. Because the active goal was still non-parked, `goal_blocks_loop_tick()` deferred the loop tick too: one lost drain stranded both automations.

The 2026-11-24 strand had loop tick #1043 admitted at 03:58:04 and its 398-second turn ending at 04:04:44. The successful judge decision updated `last_automatic_continuation_at` around 04:05, but no continuation ran until the 08:43 relay injection; the 08:48:46 loop wake was #1044. The repair leaves `_post_turn_goal_continuation` as the origin implementation and starts the normal adapter FIFO drain from the deferred bookkeeping finalizer, after the post-delivery/timeout path has run. It only drains when the runner and adapter both report the key idle, and restores the pending slot if adapter startup returns false, so an in-flight successor is not duplicated.

Contract tests: `tests/gateway/test_goal_continuation_drain.py::test_idle_post_turn_goal_continuation_starts_a_new_fifo_drain` (fails before the fix, passes after it); `tests/gateway/test_goal_continuation_drain.py::test_deferred_goal_continuation_does_not_duplicate_a_running_successor` (successor guard prevents duplicate drain); `tests/gateway/test_goal_continuation_silence.py::test_post_turn_goal_continuation_is_not_a_typed_turn` (direct hook remains queued for inspection).
