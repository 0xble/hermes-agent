# Nightly regression repairs

Load when changing process heartbeat delivery, state DB writability preflight and quarantine, or the native Copilot ACP compaction E2E.

## Required behavior

A heartbeat carries output written before it was armed and cannot follow the completion notice. A concurrent opener may quarantine a damaged state DB between a peer's `is_file` and `os.access` checks, or recreate that primary or a SQLite WAL before the failed access verdict is consumed. Revalidate the current file before refusing: a vanished path or a readable/writable replacement is not read-only. Preserve the directory check, home-scoped chmod repair, genuinely read-only refusal and WAL warning. The native ACP E2E must actually summarize an old tool result through the ACP provider while preserving the active tail and validating subsequent prompt grounding.

## Provenance and patch

Fork patch identity: `nightly-regression-0926b`.

Fork nightly [run 36274304491](https://github.com/0xble/hermes-agent/actions/runs/36274304491) at `f25c047` failed all three tests. The earlier Copilot fix in [#182](https://github.com/0xble/hermes-agent/pull/182) correctly changed missing usage to `None`, but its 15,000-token test threshold triggered immediately after the first read with approximately 17,866 estimated tokens (fixed bridge and tool schemas included), when the default protected head and lean tail left no eligible middle. Compression returned `no_progress` before any summarizer call. The scenario uses a 19,000-token trigger after older file pairs exist, **without overriding the product's default lean tail or three protected head messages**. Under `ContextCompressor._protect_head_size`, the first user/assistant/tool rows (file 1) stay verbatim on the first compaction; `_find_tail_cut_by_tokens` selects file 2 for summarization while retaining the active tail. Head protection decays after the first compaction (`_effective_protect_first_n`), so later continuation need not contain file 1 verbatim. Its assertions require a real ACP summarizer call on file 2, omission of that file from the continuation, preservation of the latest result, and a valid grounded prompt. The prior eight-read pressure estimate in [Copilot ACP usage](copilot-acp-usage.md) was not sufficient evidence that the summarizer ran.

`preflight_db_writability` identified a file before another opener renamed it into quarantine; the later `os.access` saw a missing path and raised a false read-only error. It now lets the startup lock and path recheck handle that absence. `arm_heartbeat` advanced the output cursor to data already captured by the reader, permanently omitting the early output. Heartbeat emission now checks exit under the registry lock and rechecks before enqueue to preserve completion order without holding that lock across output transformation.

Upstream design checked against `NousResearch/hermes-agent` main `9bb2ea1b5c316578d00c826833f0ba01f09d1788` (root and area AGENTS plus CONTRIBUTING). Related open [upstream PR #122852](https://github.com/NousResearch/hermes-agent/pull/122852) independently fixes the early heartbeat cursor; this fork patch also guards the completion-order race. No upstream merge or release is claimed for it or for the two other repairs.

The writable-replacement check adapts the final access revalidation from [upstream PR #142486](https://github.com/NousResearch/hermes-agent/pull/142486), merged as `ef9643393323dcf7675c467be9036aace4ee0c09`. Regressions force quarantine/recreation of the primary and a real SQLite sibling-close/recreated WAL outside the chmod scope. This does not establish the exact interleaving of an earlier hosted failure.

The absent-path guard alone does not cover an absent-then-recreated database between `os.access` and the later existence check. Teknium's upstream [quarantine-lock preflight repair](https://github.com/NousResearch/hermes-agent/commit/8c118f7834d0f66639e4198efb9c8b9bd2c2ccee) and [directory-before-lock repair](https://github.com/NousResearch/hermes-agent/commit/59b70c943a5f3504e03dab0b2ed4ceb3a8b32848) from merged [PR #140511](https://github.com/NousResearch/hermes-agent/pull/140511) arrived with the upstream sync and are not fork code. The fork patch narrows upstream's unlocked branch: only a positively observed SQLite header permits unlocked preflight. Missing, invalid, unreadable or deliberately skipped header probes retain the existing quarantine lock through file/sidecar permission repair, quarantine, connection and schema commit. An unreadable damaged file must not enter the unlocked branch and become eligible for quarantine only after its permissions are repaired. Directory repair stays before lock creation. Retain the fork's absent-path guard and live-connection byte-probe guard. `tests/hermes_state/test_zeroed_db_quarantine_race.py` keeps upstream's mid-quarantine test and adds the fork's absent/recreated interleaving outside HERMES_HOME and the unreadable-file permission-repair interleaving inside it, each with 2 real openers, real filesystem results, retained canonical sessions and forensic backup integrity.

## Verification and retirement

Run `scripts/run_tests.sh --file-retries 0 tests/hermes_state` for the quarantine/preflight integration, including read-only refusal, directory-before-lock repair, concurrent no-clobber quarantine, forensic backup and integrity. For the remaining repairs, run `scripts/run_tests.sh --file-retries 0` on `tests/e2e/core/providers/test_native_copilot_acp.py` (Linux non-root) and `tests/tools/test_process_heartbeat.py` in a pinned Linux CI container. The forced quarantine preflight race and heartbeat ordering tests are event-synchronized. Run `scripts/check_fork_patches.py --repo . --source-only` with a clean HOME and HERMES_HOME after committing.

Retire the fork patch only after the accepted upstream release has equivalent behavior and all focused regressions pass without these local changes. Reverting a single aspect requires retaining its invariant test and reassessing this unit's scope; no stored-state migration is involved.
