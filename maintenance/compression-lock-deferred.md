# Compression-Deferred Turns

Extends the [fork contract](../MAINTENANCE.md). Load for gateway admission, hygiene turn-hold, pending-input draining, or compression-lock changes. No independent schedule.

## Preserve

- Compression owns its transcript until its fenced commit. Neither a fresh turn nor the turn that started hygiene may enter model preflight against that snapshot while the lock remains held.
- Retain accepted human and gateway inputs silently. Authority-owned native turns retain their started admission and FIFO position while awaiting the compression lease; they never transfer durable ownership to an adapter RAM slot. Non-authority inputs retry in the owning adapter task with the existing bounded requeue backoff, keeping their pending slot visible for FIFO admission and shutdown recovery.
- Keep distinct events and their provenance, goal/loop fences, source pins, and outbox admission identities intact. An initiating input precedes arrivals queued during its hygiene wait.
- Defer goal/loop post-turn bookkeeping until execution. Slash controls remain available while model work is queued.

## Provenance and Patch

- **Identity:** `compression-lock-deferred`, maintained fork implementation.
- **Durable-admission boundary:** an unexecuted compression deferral is an explicit executor outcome, not an empty model result. The claimed admission remains started, later arrivals remain queued, and the same claim re-enters the handler after commit to load current history. Stop/new cancel without a model call; drain/restart use the existing zero-API-call recovery path. `tests/gateway/test_compression_admission_retry.py` exercises real authority, native envelope restoration, settlement, adapter lifecycle, and transcript writes in an isolated DB. The transport-only tests mock the handler and cannot prove this boundary.
- **Surfaces:** `gateway/session_ingress.py`, `gateway/session_results.py`, `gateway/run_busy.py`, `gateway/run_inbound.py`, `gateway/run_turn.py`, `gateway/platforms/base.py`, `tests/gateway/test_compression_admission_retry.py`, `tests/gateway/test_compression_deferred_retry.py`, `tests/gateway/test_compression_retry_lifecycle.py`, `tests/gateway/test_bot_loop_guard.py`, and `tests/gateway/test_session_race_guard.py`.
- **Failure mechanism:** watermark-fenced hygiene keeps running after the inline hold expires. Returning the old transcript allowed preflight to collide with that worker's durable lock and consume each input as another retry response, including gateway wakes.
- **Related upstream:** [NousResearch/hermes-agent#134244](https://github.com/NousResearch/hermes-agent/pull/134244), open when checked on 2026-10-22, covers the fresh-turn admission gap. It does not cover the initiating turn that starts hygiene after admission, and its external refusal requires a resend.
- **Adaptation:** apply one silent deferral mechanism at admission and after hygiene. Reuse existing FIFO ownership, adapter draining, requeue backoff, and compression leases. Do not merge events across control or identity boundaries. While a dispatched head awaits admission, refill an empty pending slot from older overflow before appending a new arrival.
- **Cancellation ownership:** fence cancelled finalizers only when a caller explicitly takes over the pending slot. `_hermes_pending_owner` is task-local, set before cancellation: the command tail replays, shutdown spools, and discard-mode cancellation drops pending work. Unmarked preserve-mode cancellation retains the base finalizer drain; the existing compression-self-requeue and drain-deferred shutdown fences remain. `tests/gateway/test_cancelled_command_tail_ownership.py` checks real `/stop` tail ownership, internal-before-human FIFO, and zero requeue counts at dispatch rather than a wall-clock gap. `tests/gateway/test_cancelled_retained_successor.py` checks retire-now's preserve-mode call drains `first` then `wake`, leaving no pending input.

### Session-task cancellation caller audit

Audit `cancel_session_processing`, every `.cancel()` in `gateway/`, `_session_tasks` references, and cancellation helpers when adding a caller. The two production `cancel_session_processing` callers and both direct adapter session-task cancellation sites are below; expected-cancellation bookkeeping alone does not transfer pending ownership.

| Caller / cancellation site | Pending owner and required behavior |
| --- | --- |
| `platforms/base.py::_dispatch_active_session_command` → `cancel_session_processing(release_guard=False, discard_pending=False)` | Marks `command_tail` after the inline reply and before cancellation. `_drain_pending_after_session_command` replays retained FIFO work under the command guard; the obsolete finalizer must not spawn a successor. |
| `telegram_retire.py::request(now=True)` → `cancel_session_processing(discard_pending=False)` | No takeover marker. Interrupt only; the cancelled finalizer drains retained obligations in FIFO order. Retirement must not strand an internal wake. |
| `platforms/base.py::cancel_session_processing` → recorded session `task.cancel()` | Preserve mode inherits the caller's marker or drains when unmarked. Default `discard_pending=True` marks `discard`, then removes pending/debounce work itself. No other production callers currently use default discard mode. |
| `platforms/base.py::cancel_background_tasks` → tracked background `task.cancel()` | Marks `shutdown_spool` before every cancel. `_flush_owned_pending` (or standalone `flush_pending_to_file`) persists retained slots; cancelled session tasks must not replay. |
| `run_adapters.py::_bounded_adapter_teardown` and `run_startup.py::_startup_teardown_adapter` → `cancel_background_tasks` | Shutdown/replacement/startup-abort teardown delegates to the same spool owner, not a separate replay owner. |

Other gateway `.cancel()` sites target batching/debounce and typing timers, transport/connect/reconnect workers, runner background coordinators, completion injectors, replay workers, turn-side progress/stream/tracking tasks, shared-runtime admission/authority tasks, API-server private agent tasks, and futures/native I/O. They do not cancel `BasePlatformAdapter._session_tasks` owners. `platforms/helpers.py::cancel_task` has no gateway callers; shutdown cancellation-grace helpers target cron batches. No third direct adapter session-task cancellation site was found.

- **Upstream comparison:** main `323c318c4eb4a22fd75e9172639d88379bbc3d42` lacks a general cancelled-finalizer admission fence. Open [handoff PR 106700](https://github.com/NousResearch/hermes-agent/pull/106700) tracks command ownership through guard attributes; open [backoff PR 123259](https://github.com/NousResearch/hermes-agent/pull/123259) retains the original self-requeue design. Neither is adopted here: the fork already has a dedicated compression lifecycle, deferred-control ordering, and shutdown spool. Reconcile those contracts before retiring this narrower guard. Fork delivery remains local-only pending parent verification, with no upstream submission.
- **Earlier fork candidate:** [0xble/hermes-agent#667](https://github.com/0xble/hermes-agent/pull/667) remained unmerged when this boundary was reconciled. Its older coalescing implementation predates the current FIFO provenance rules.
- **Distinct prior fix:** [0xble/hermes-agent#687](https://github.com/0xble/hermes-agent/pull/687) preserves proactive-prune replay versions and does not provide compression-locked input retry.

## Verify and Recover

Run `scripts/run_tests.sh tests/gateway/test_compression_admission_retry.py tests/gateway/test_compression_deferred_retry.py tests/gateway/test_compression_retry_lifecycle.py tests/gateway/test_session_hygiene.py tests/gateway/test_session_hygiene_turnhold_adoption.py tests/gateway/test_busy_requeue_hot_loop.py tests/gateway/test_busy_session_ack.py tests/gateway/test_bot_loop_guard.py tests/gateway/test_session_race_guard.py -q`.

The regression owns a real SQLite compression lock, expires the initiating hygiene wait, admits 2 additional inputs before commit, and requires automatic drain with no retry notice, busy acknowledgment, or early model execution. Ordinary busy acknowledgments remain available when compression is not holding the session. Controls and event identity have separate coverage. A helper-only probe cannot establish gateway integration or live delivery.

There is no schema, configuration, prompt, dependency, or compression-threshold change. Adapter typing and processing-start hooks run once for the retained input and remain pending across retries. A retry does not restart those producers, complete delivery, or run a post-delivery callback. Runner model execution and progress producers start only after admission clears. Ingress rewrites, last-inbound stamps, and bot-budget admission run once, while authorization and cooldown checks remain live. Queue-mode debounce batches ordinary unheld human text. Before the shared FIFO admits a newer input, it transfers any older debounce burst and cancels that burst's timer without yielding. While compression owns the lane or its retry head remains visible, busy admission retains each later input in the existing FIFO instead of a debounce buffer. This preserves order across human text, external relay envelopes, and internal wakes, including the lock-acquire and lock-release/backoff boundaries. Never merge a retained input, including a photo with a later caption, or an internal wake or control/provenance boundary. Roll back only this unit's gateway changes and registration, preserving unrelated compression and queue fixes.
