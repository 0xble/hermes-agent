# Plugin and hook dispatch gates

- Fork patch identities: `plugin-hook-identity`, `plugin-hook-shell-gate`, `plugin-hook-shell-backoff`, `plugin-hook-disk-state`, and `plugin-capability-log-level` (`Fork-Patch:` trailers).
- Required behavior: concurrent lifecycle and nested RPC tool calls keep distinct callback gate identities; shell hooks retain their matcher, timeout, and `fail_closed` policy, skip inapplicable hooks before forking, and back off repeated fail-open timeout/spawn failures; disk-cleanup state writes never race on a shared temporary path; default ungranted capability checks do not flood INFO logs while grants remain auditable.
- Upstream prior art: related open PRs [#125737](https://github.com/NousResearch/hermes-agent/pull/125737) and [#129158](https://github.com/NousResearch/hermes-agent/pull/129158) for session identity fallback; issue [#132096](https://github.com/NousResearch/hermes-agent/issues/132096) and draft PR [#132111](https://github.com/NousResearch/hermes-agent/pull/132111) for shell-hook self-gating; issue [#132943](https://github.com/NousResearch/hermes-agent/issues/132943) for disk-cleanup concurrent state writes; open PR [#100324](https://github.com/NousResearch/hermes-agent/pull/100324) for DEBUG-level default capability denials. No upstream issue or PR was found for shell-hook timeout backoff, suppression, or a declarative `requires_env` applicability field.
- Design: keep the dispatcher gate for ordinary Python policy callbacks; add `session_id` only as the final identity fallback and mint a unique `tool_call_id` (`nested_tool_call_id`) for every nested execute_code call, on both the remote RPC loop and the local session kernel's `CellAuthority`. Shell callbacks expose their parsed spec so the existing dispatcher can check applicability before gating and bound above the shell timeout. Reuse `utils.atomic_json_write` for unique temporary files while copying `.bak` first. Log only the expected `evidence=not granted` deny at DEBUG.
- Retirement: remove each local implementation only after the corresponding upstream behavior is merged and released, and the selected upstream release passes these regressions without the local implementation. The session fallback may retire after either #125737 or #129158 releases the complete session identity behavior; the RPC identity and disk/capability changes require matching released upstream coverage, not merely an issue or open PR.
- Out of scope: concurrent disk-cleanup writers can still race on the in-place `.bak` copy and lose each other's read-modify-write entries; this unit removes only the shared temporary-file crash.
