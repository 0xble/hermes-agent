# Install and Scratch Garbage Collection

Patch identity: `install-scratch-gc`.

Hermes records the resolved checkout beside each dependency install and collects an install only after the checkout is gone, the install has been idle for a day, its non-blocking install lock is available, and no dependency-generation lease is held. Legacy installs without the sidecar are judged by tree activity and collected after three idle days when their key matches no visible checkout. Each removal first renames the install under its lock to a `.gc-` name outside the key space, so an interrupted delete leaves no remnant that looks live or legacy; the next pass finishes it. The gateway housekeeping loop runs the collection on its own thread, at most ten installs per pass and never two passes at once. Release publishes also run it, but agents create and delete a worktree per task, each with a full environment, so without the hourly pass orphans accumulate by the hundred between publishes. Upstream's `pm/install_states.py` reclaim stays as is; it covers only checkouts directly under a `.worktrees/` directory or the data root, and runs only beside the worktree pruner.

Both the gateway's install-orphan collection and the cron tick's periodic worktree pruner delete only inside `maintenance.deletion_window` (default `02:00-05:00` local, `hermes_cli/maintenance_window.py`; empty allows any time). On 2026-10-11 daytime mass deletes on a nearly full APFS volume stalled state.db writers and the gateway for 10-15 minutes. Inside the window the install collection runs every 5 housekeeping ticks; outside it, the cron pruner leaves its 6-hour throttle unspent so it runs once the window opens. Interactive `hermes -w` startup pruning is unchanged.

Scratch maintenance must still run when macOS exports `TMPDIR`; honoring that user/OS temp directory must not bypass Hermes' scratch-tree pruner.

The scratch pruner treats idle as not unused. Before reaping processes and again right before removal, it reads the retention declarations the host storage cleaner already honors: a `.keep` anywhere in an entry (outside `node_modules` and virtualenvs) pins that entry, and an entry's top-level `input-pins.json` pins the entry plus every scratch entry that holds one of its declared paths, followed transitively and compared by realpath. An unreadable declaration keeps every idle entry for that pass, because its dependencies cannot be ruled out. A declaration lasts until its owner deletes it. There is no lifecycle registry.

Guard tests: `tests/pm/test_install_gc.py` covers orphan, live, leased, locked, and legacy installs, the per-pass limit, and finishing an interrupted removal. `tests/gateway/test_install_orphan_housekeeping.py` covers the housekeeping chore collecting an orphan idle past a day while keeping a younger orphan and a live checkout's install. `tests/test_scratch_dir.py::test_user_tmpdir_does_not_disable_scratch_pruning` covers the macOS boot path, and the `test_prune_*` retention tests in the same file cover pinned, transitive, unreadable, `.keep` and re-read cases.

Retire when equivalent upstream behavior is present and the guard tests pass without this fork patch.
