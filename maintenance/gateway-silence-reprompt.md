# Gateway human-turn silence re-prompt

This unit owns one gateway-level recovery execution when a locally executed human-addressed turn ends on a bare silence marker.

## Preserve

- Evaluate `silence_allowed(display_kind, reply_expected)` **after execution**, from the live gateway `TurnContext`. The real busy fold in `gateway/run_busy.py` changes a relay's `reply_expected=False` to `None` when a genuine typed request is absorbed. Relay-only, machinery, failed, interrupted, and stale executions must not start this retry.
- After the first stream's existing end-of-turn silence filter finishes, call the gateway's recursive `_run_agent` continuation once. Keep session/source/run generation, latest reply anchor, typed history, tool results, and the outer persistence offset. Do not re-run the original request or completed tools.
- The retry's own result is terminal: tools, stop gates, compression, or another folded message cannot renew its budget. A second bare marker reaches the unchanged human-turn visible fallback. A separate queued or subsequent genuine human turn gets its own retry.
- Recovery guidance uses the existing API-only ephemeral system prompt, not an assistant/user nudge pair. Only the guidance is ephemeral; the first execution's messages, including its marker, continue as history. Append the note to the resolved agent's `ephemeral_system_prompt` only after cache resolution and restore the stable prompt in a `finally` (success, failed result, exception, approval failure). The cache signature, cached `AIAgent`, frozen system prompt, and tools must be identical across normal → recovery → normal; never add a signature-ignore case or second cache. The continuation's empty runtime row carries `internal_notification` provenance; its final per-call wire copy alone receives a non-empty continuation cue so strict providers accept the request. Never stamp that cue in `api_content`: restore its scoped agent attribute along with the ephemeral prompt on every exit. The empty runtime row cannot replace the latest genuine user ask, session title, or inbound delivery anchor. The note is absent from live/result message history, SQLite content and sidecars, trajectories, compression input, and subsequent queued turns. No agent transcript scaffolding or compressor-specific flags belong to this patch.
- Compaction may attach a reference summary to the retained typed steer for provider alternation. The shared user-origin projection and compressor selectors must still recognize its live human payload, while standalone handoffs and operational display kinds remain synthetic. Unwrap only for classification, never promote summary prose to an active ask.
- A queued terminal turn owns its own silence verdict; absent a genuine successor, the original human verdict and inbound ID must survive the internal retry. Never allow the retry's internal display kind to legalize a second marker.
- Fresh execution means a fresh stream consumer. Bare-marker segment previews must be held back on edit, native, and stream-is-the-message draft transports. Cumulative adapters keep earlier tool preambles while removing only the rejected final segment; neither the first marker nor its retry may appear in sent, edited, or native/draft frame payloads. An intermediate (segment-break) bare marker is removed in place: truncate to the retained preamble and keep the cumulative stream or native bubble open for later segments. Final-text adoption and delivery reconciliation must both combine the retained cumulative preamble with the last assistant answer (without duplicating an already-cumulative final), so `finish(final_text)` cannot erase the preamble or trigger a corrective duplicate send. Only terminal suppression closes an open native stream with the retained preamble through the existing boundary finalizer before recovery starts, without claiming turn-final delivery. Non-cumulative transports keep deleting only the marker segment's previews.
- A delivered, intentional reaction to the current human message counts as its reply. Carry the receipt only within that turn and target, including worker-thread context and queued-message rebinding. Successful blank or bare-marker finals then skip recovery and the visible empty-response warning. Failed reactions, unrelated targets, stale receipts, failed turns, and incomplete turns must preserve the existing fallback.
- Expose the existing `react` tool on messaging platforms through `BasePlatformAdapter.add_reaction`, preserving the desktop path. Unsupported adapters fail clearly. Slack uses the session workspace and accepts shortcode or mapped Unicode reactions. Telegram validates the supported reaction set before transport.
- Proxy turns do not get this retry; the existing human-turn warning remains. The API requires non-empty final conversation content and cannot represent an empty internal continuation: a system-only/empty-row request returns 400, while omitting the empty row makes the preceding assistant marker new user input. Do not change API-server validation or invent a persisted user nudge to work around that contract.
