## Accepted behavior

- Child execution outcome is independent of parent result disposition. Exact terminal attempts may be `incorporated`, `blocker_report`, `deferred` (nonempty short reason), or `revision_requested` (only proven successfully started linked continuation/replacement). Arrival, prose and steering never attest acceptance.
- Track only exact results actually presented in a particular parent processing turn. Independent async completion units must derive refs and attempts from their actual result entries, not call-wide metadata. Coalescing preserves all and only admitted units' attempts; early failures retain exact unit identity.
- After the original loop returns, missing dispositions receive one narrow hidden correction under the existing admitted turn lease. At most **two provider requests**; no summary fallback, retry loop, compression/title/memory auxiliary request, model-route fallback, or new tool authority. SDK retries are disabled on the native request clients. Unsupported/fan-out transports fail closed to the warning instead of exceeding the bound.
- Silence every host prose channel for that correction, including stream deltas, interim assistant, host stream/TTS callback, reasoning, status and tool callbacks. Direct forced `_vprint` output is also suppressed via `suppress_status_output` and `_print_fn`. Restore callbacks and settings in `finally`. Only owning ledger control events pass through. Neither hidden model prose nor its tool results may replace or preview the original answer.
- Failed/omitted correction preserves unresolved visibility and delivers the original answer with an honest actionable warning. Unrelated user arrivals are never gated on historical unresolved results. No cached-prefix or tool-schema mutation, injected fake user mid-loop, automatic acceptance, or infinite loop.
- Incorporation/blocker intent is durable before its response; retirement requires exact verified delivery. Deferred reasons remain visible. Recovery is exact-owner and idempotent, never age-based.
- A later ordinary turn may deliberately call `delegate_task(action="result", delegation_id=<exact persisted unit>)`. Every terminal dispatch path (synchronous, no-async fallback, capacity fallback, and mixed inline) first archives its exact result in the existing durable result ledger and exposes its `result_delegation_id`. These archives have no async event and are not scheduled for redelivery. Named result payloads (async and inline) remain durable before presentation and throughout deferral, independent of notification admission, acknowledgement, drop, in-memory eviction and age/count history pruning. The existing ledger records release only for exact immutable owner/ref/attempts proven handled-and-delivered, or a successfully admitted linked revision/replacement. Once released, ordinary settled history retention applies, including inline archives; both inline archive creation and exact release invoke existing settled-history pruning, so synchronous-only use is bounded without a later async dispatch. Pending notification delivery/retry is unchanged. The ledger verifies the complete immutable owner. The tool returns the actual terminal result and its exact refs/attempts; normal executor presentation registers that result in the current turn. Retrieval itself does not acknowledge it. Listing/spawning/ordinary history never registers terminal presentation. Superseded attempts cannot attest a newer attempt.
- Same-session continuation validates durable parent ownership, frozen primary/fallback/credential authority, cwd, persisted checkpoint, pending tool results and native session lease. Only successful admission links the precise prior attempt. Rejection or ambiguity never accepts it or launches duplicates.
- Eligible interrupted children retain their durable session, logical card row, label and hierarchy; only internal attempt generation changes. No new Recover thread or context reset. Expose the durable resume handle through normal result/control workflow. User-stopped/foreign work is not automatically resumed.
- A completed terminal tool receipt is **not** completion of a background command. One atomic owned-process registry snapshot must show no running, exit-transition, or unreconciled process, including silent jobs, before a resume grant. A session still in the running registry blocks even if `exited=True` and already polled; the reader holds the registry lock through finished-state persistence. Process accounting precedes the checkpoint, and blockers are durable before the result advertises continuation. Registry failure is fail-closed. Finished-cache TTL/cap eviction cannot erase an unresolved raw-owner/process fence: the existing redacted, output-size-bounded process receipt persists exact observation state independently of memory. Unobserved delegated or unknown-owner receipts outlive ordinary 7-day/64-settled history retention; exact poll/log/wait or output-consuming reconciliation releases that obligation. Existing durable session metadata may prove ordinary non-delegated conversation ownership (root non-subagent/tool source without delegation config, or a verified same-source compression lineage); only that history receives the ordinary age/count budget without claiming observation. Missing metadata, child source/authority, and ambiguous lineage remain conservative. An ended child or old raw task ID is never proof of reconciliation. Gateway queue arrival/drain is not observation. History scans and pruning run outside the registry lock; a finish/eviction generation check retries the disk scan if publication crossed its boundary, then combines retained and live state under the lock. Observation state survives restart without replaying notifications or adopting PIDs. Only literal `result_observed=true` is proof: base-format missing, null, or mistyped flags stay unobserved through restart and age/cap pressure. Unreadable or malformed receipt identity/required data is preserved, not pruned. Healthy ordinary retrieval continues independently. Intact exact receipt identity/raw owner, or consistent existing checkpoint identity/owner, localizes corruption to that owner; that owner stays blocked while unrelated owners can resume. Irrecoverable unknown or conflicting ownership blocks all owner-based resume checks, but never blanks healthy user-facing history. No owner is guessed and no index/service is added. Failed receipt publication preserves the in-memory fence and a bounded force-redacted completed snapshot in the existing process checkpoint; it is retained across successful checkpoint rewrites and recovered only as a completed result, without PID probing/adoption, watchers, deadlines or replayed notices. Malformed checkpoint entries are retained as originals across subsequent writes and keep their scoped/unknown-owner uncertainty, while later healthy live entries and watchers recover normally; a malformed completed fallback is never considered a PID candidate. Exact observation retries receipt publication; a newer exact durable receipt wins over a stale fallback checkpoint when cleanup writing failed. History pruning errors do not undo a successful receipt write. This does not guarantee recovery when both durable writes fail, nor recover externally deleted storage. Cleanup cannot turn an uncertain effect into a safe replay.
- Preserve symbols: running `○`, queued `◌`, returned `✓`, failed `!`, interrupted `Ⅱ`; tools retain `↳` and their canonical icon/name. Visible cards do not expose internal IDs.

## Implementation boundaries

`tools/async_delegation.py` owns durable async results/admission and immutable ownership. `gateway/delegation_cards.py` owns durable handling intents/projection; `gateway/delivery_ledger.py` owns verified outbound receipts/replay. `TurnRunner.progress_callback` bridges tool actions to the card lifecycle. `agent/turn_facade.py` retains the native lease wrapper; `agent/delegation_correction.py` is an explicit bounded sibling path, not the normal loop's budget-summary finalizer. It reuses native request assembly, normalized responses, the tool executor and persistence. The shared request messages/system/tools stay stable.

The bounded correction verifies the actual native SDK client (not an api_mode label) before staging repair and again at physical dispatch. It supports native chat-completions, Anthropic Messages, and Codex Responses. Codex uses its required SSE transport with SDK and stream-reconnect retries disabled; host streaming/printing stays suppressed. Virtual ACP clients are rejected before repair. Fan-out/MoA and transports whose internal request count is not bounded here do not run a hidden repair; the original answer plus unresolved-result warning is the conservative outcome. Hidden `handle` calls are restricted to the supplied task/refs. No provider/config rewriting or reduced reasoning is used.

Resume reuses `SessionDB.claim_delegated_resumes` and `admit_durable_turn_lease`. Legacy rows lacking frozen logical-card metadata fail closed; mixed fresh/resumed dispatches and unrelated original batches remain separate. Primary-authority diagnostics expose fixed field names only (provider, model, api_mode, base_url, authority, request_overrides), never values/fingerprints or re-pinned credentials. Nested result incorporation remains direct-parent scoped and cannot borrow a root delivery receipt.
